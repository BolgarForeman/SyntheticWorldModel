WORK ORDER 3 — Layers stage, coordinates at Point Nemo, and the first GIS export

Branch: wo3/layers. It already exists on GitHub, holding this work order and docs/design/World_Generator_Structure.md updated to v0.4 (the coordinate ruling). Build on it.

Goal: put the infrastructure on the ground. From the resolved recipe, the terrain result and the layers/* streams:
- site every node of all six layers;
- give each node its class and observed attributes;
- build each layer's own links;
- anchor it all at Point Nemo in EPSG:32710, so the world opens in ArcGIS and loads into PostGIS.

As before, the output is the same bytes on Windows and Linux.

Spec: World_Generator_Structure.md v0.4: §3 (principles, including the synthetic centroid), §4.1a (coordinates), §4.2 (layers and sources), §5 (end-use classes). Pilot_Spec.md v0.4. CLAUDE.md. Decision records 0001–0005, and 0006 below.

PART A — COORDINATES (src/swm/coordinates.py)

A1 Anchor and projection.
  - The synthetic centroid is Point Nemo: 48.8767° S, 123.3933° W. Record it as a named constant with its source (the Pacific pole of inaccessibility).
  - The working projection is WGS 84 / UTM zone 10S (EPSG:32710).
  - The terrain domain's centre sits on the centroid's projected coordinates. The generator's local metres become EPSG:32710 metres by a fixed offset. This is pure addition, so the world-building arithmetic rule still holds.

A2 Latitude and longitude.
  - A function converts EPSG:32710 metres to WGS 84 latitude/longitude using pyproj (MIT; add it as a runtime dependency).
  - Round to 7 decimal places, as spec §4.1a says.
  - This is the one sanctioned use of transcendental arithmetic, and it is quantised. Name it so in a comment.
  - Axis order is always longitude, latitude (always_xy).

A3 Tests:
  - a round trip, metres → lat/lon → metres, within 1 cm across the domain;
  - the pilot's node latitudes/longitudes are checked in as golden values, and CI reproduces them on both platforms;
  - the centroid's own coordinates reproduce exactly.

PART B — THE LAYERS STAGE (src/swm/stages/layers.py)

B1 Scope.
  - All six layers, for every size up to the Phase 1 limit.
  - States:
    - emitted and hidden layers are both generated in full (hidden differs only at emission);
    - off layers are not generated.
  - The nodes-only flag is recorded but changes nothing here: the links exist in the truth whatever the flag says.
  - Dual membership: when it is on, one reservoir on a river is also a generation node (a hydro dam), and it counts in both layers. The pilot has it off.
  - Draw only from the layers/* streams.

B2 Node classes. Each layer's nodes are split across its classes by a composition table:
  - sized by node count;
  - at least one of each backbone class, where the count allows;
  - held in one table, marked CHOICE, placeholder (open decision: realism ranges).

For the pilot's 4 nodes per layer, the composition is fixed as follows (ruled by the author, 2026-09-28):

  | Layer | Pilot composition (4 nodes) |
  |---|---|
  | Power | 1 generation plant, 1 transmission substation, 2 distribution substations |
  | Telecom | 1 exchange, 3 masts |
  | Water | 1 reservoir, 1 treatment plant, 1 pumping station, 1 storage |
  | Transport | 1 seaport, 1 airport, 1 freight yard (truck warehouse and yard), 1 bridge |
  | Fuel | 1 import terminal, 1 tank farm, 2 depots |
  | Healthcare | 1 tertiary hospital, 1 regional hospital, 1 clinic, 1 blood bank |

That gives the pilot 15 end-use nodes to score: 2 distribution substations, 3 masts, 1 storage, the seaport, the airport, the freight yard, 2 depots and all 4 healthcare facilities. The bridge is not an end use; it matters through what it connects.

Add freight_yard and bridge to the transport node classes. The freight yard joins the end-use classes with Lifeline weight 4 (the same as a fuel depot: the point where goods reach users, with stock that buffers short outages). The bridge takes no weight.

B3 Siting rules. Nodes are sited on land cells, never on river or wetland cells (bridges excepted, below). Choose by weighted draws among eligible cells, so siting is quietly varied, never a fixed "best cell" that a shortcut could recover. Each rule's weights go in one CHOICE table.
  - Power:
    - generation on the coast near a city (thermal or LNG), or on a mountain river when it is a hydro dam;
    - transmission substations between generation and the cities;
    - distribution substations in or beside cities, one per city first.
  - Telecom:
    - the exchange in the largest city;
    - masts spread across towns, open land and high ground, spaced apart.
  - Water:
    - the reservoir on a river in the uplands;
    - treatment downstream toward the largest city;
    - pumping between treatment and the city;
    - storage on raised ground beside a city.
  - Transport:
    - the seaport on the coast at a city, preferring an indented (sheltered) shore;
    - the airport on flat lowland near a city, needing a flat run of at least 2.5 km (CHOICE);
    - the freight yard on flat land near the seaport's city, close to the main road;
    - the bridge where the road between two cities crosses a river. It sits on a river cell, the one sanctioned exception to the no-river-cell rule;
    - in larger worlds, road junctions in cities and then between them, and rail nodes if rail is on.
  - Fuel:
    - the import terminal on the coast, preferring the seaport's city;
    - the tank farm near the terminal;
    - depots in cities.
  - Healthcare:
    - the tertiary hospital in the largest city;
    - the regional hospital in the second city (or the largest, if there is only one);
    - clinics in towns or rural land;
    - the blood bank in the tertiary hospital's city.

B4 Observed attributes. Generate the scored attributes the schema lists per layer (location, class, capacity, type, status, voltage class, bed count, size class, operator):
  - capacities scale with the population the node serves, using city footprint as a proxy for size (not a demand field);
  - value ranges go in one CHOICE table, placeholder (open decision: realism ranges);
  - status is "operational" for all in Phase 1.

B5 Intra-layer links, each layer keeping its signature (spec §4.2):
  - power meshed: generation → transmission → distribution, plus ties among transmission substations;
  - telecom a star from the exchange, with some mast-to-mast links;
  - water dendritic: reservoir → treatment → pumping → storage, a tree;
  - transport a road network joining the seaport, freight yard, airport and cities, with the bridge on the road that crosses the river;
  - fuel a supply tree: terminal → tank farm → depots;
  - healthcare a referral tree: clinics → regional → tertiary, with the blood bank linked to the hospitals.

Build the signature's spanning structure first. Then add nearest-first links until the layer's mean links per node reaches the recipe value, within rounding, and report the realised value. Every layer must be one connected component.

Links are straight segments in Phase 1, with length in km recorded. Terrain-following routes are Phase 5. Record that in the decision log.

B6 Identifiers. Internal ids are synthetic and stable, for example SWM-POW-0001. Source-specific identifiers (OSM ids, WRI ids and so on) belong to emission, not here.

B7 Output: a frozen dataclass holding:
  - a node table: id, layer, class, x_m, y_m in EPSG:32710, latitude, longitude, city id, observed attributes;
  - a link table: id, layer, from, to, length_km;
  - the layer states;
  - realised statistics per layer: count by class, mean links per node, mean nearest-neighbour spacing in km.

No file writing inside the stage.

PART C — INSPECTION EXPORT AND PREVIEW

C1 `swm export-gis RECIPE -o OUT_DIR` writes:
  - world.gpkg: layers nodes, links, cities, coastline, each in EPSG:32710;
  - GeoTIFFs of elevation (m), land cover and rivers, in EPSG:32710 with correct geotransforms.

Every file's metadata says "SYNTHETIC — not a real place; anchored at Point Nemo". Use pyogrio with shapely for the GeoPackage and rasterio for the GeoTIFFs (all permissive), in an optional "export" group. These files are outside the identity check (spec §4.1a).

Test that they open and read back the right feature counts, the right CRS and the right bounds.

C2 `swm preview-world RECIPE -o OUT.png`: the terrain preview with every node (colour by layer, shape by class) and every link drawn over it, plus a legend and a caption of per-layer statistics. Post the pilot's in the pull request.

C3 `swm layers RECIPE -o OUT_DIR` writes layers_stats.yaml and layers_sha256.txt (node and link tables, in canonical form).

PART D — TESTS
  - Identity (golden): the pilot's node and link tables and statistics reproduce byte for byte on both platforms.
  - Counts: exact per layer and per class, for the pilot and for random valid sizes up to the Phase 1 limit.
  - Siting:
    - no node falls on sea, river or wetland;
    - seaport and import terminal are on the coast;
    - the airport has its flat run;
    - the exchange and the tertiary hospital are in the largest city;
    - the reservoir is on a river above the treatment plant.
  - Links:
    - each layer is one connected component with its signature (water and fuel are trees; power has at least one cycle);
    - realised links per node is within 0.5 of the recipe's.
  - States: a hidden layer is generated in full; an off layer is absent; nodes-only changes nothing in this stage.
  - Streams: only layers/* streams are drawn, and the terrain is unchanged by any layer setting.
  - Property: random valid layer sections keep all the invariants above.

PART E — FOLLOW-UPS (record as docs/decisions/0006-wo3-rulings.md)

E1 Peak height. After relief is carved, rescale elevation so the highest point equals 100 m + mountainous/100 × 3,900 m, to within 1 dm. Add a test. The pilot's peak becomes 2,440 m, and the terrain golden hashes change once more; say so in the pull request.

E2 Source scope and the OpenStreetMap backbone. This mirrors the real corpus: OpenStreetMap is the backbone source on every layer, and the specialised sources cross it.
  - Each source declares which node classes it can carry, from what the real source contains:
    - each OpenStreetMap source carries every class in its layer;
    - WRI carries generation only;
    - OurAirports carries airports only;
    - World Port Index carries seaports only;
    - the facility register carries healthcare facilities;
    - and so on.
  - Put the scope table in the schema, with a source note per row.
  - A world node whose class no switched-on source covers is real but unemitted, and the truth manifest records it.
  - Rename the source osm_roads_rail to osm_transport ("OpenStreetMap transport"). Its scope is every transport class: roads, rail, bridges, ports, airports and freight yards.
  - OpenInfraMap is built from OpenStreetMap, so it is not an independent source. Record in the source note that its errors are correlated with OpenStreetMap's. Error induction will treat it that way; nothing more is needed here.

Pilot sources:
  - OpenStreetMap on every layer;
  - power adds WRI;
  - healthcare adds the facility register;
  - transport adds OurAirports.
So power, healthcare and transport each have a specialised source crossing the backbone. Update the pilot fixture to match.

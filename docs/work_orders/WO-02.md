WORK ORDER 2 — Spine-island terrain stage, and the Work Order 1 follow-ups

Branch: wo2/terrain. The branch already exists on GitHub. It holds this work order, docs/design/World_Generator_Structure.md updated to v0.3 and docs/design/Pilot_Spec.md updated to v0.4. Build on it; do not start a new branch.

Goal: the first real stage. From the terrain section of a resolved recipe and its terrain streams, build the ground for a spine island: elevation, coastline, drainage, land cover and urban extents. It must be the same bytes on Windows and Linux. This stage sets the pattern every later stage follows: a pure function from recipe section, earlier outputs and named random stream to a frozen result, with tests that pin its behaviour.

Spec: World_Generator_Structure.md v0.3, §3 and §4.1. CLAUDE.md §4–§7. Decision records 0001–0003, and 0004 below.

PART A — THE TERRAIN STAGE (src/swm/stages/terrain.py)

A1 Scope. The spine island is the only map type built. All other map types stay refused by the buildability check (Phase 5). The stage reads recipe.terrain, root_seed and terrain_seed, and draws only from the terrain/* streams already registered.

A2 Domain and area. area_km2 is the target land area, not the map area.
  - Build the shape in normalised coordinates.
  - Measure its land fraction.
  - Size the square domain so the land area matches area_km2, to within cell quantisation.
  - Report the realised land area.
  - Use a fixed grid of 256 × 256 cells for every area in Phase 1, and record the cell size in metres. Mark the grid size CHOICE; it is revisited at scale.
  - Coordinates are local metres from a domain origin. They are not tied to any real place. The latitude/longitude anchor is open decision 9, and no emitter needs it yet.

A3 Elevation (spine island).
  - An elongated island along a spine drawn as a smooth curve through seeded control points (a polynomial spline, not trigonometric).
  - The ridge profile falls from the spine to the coast.
  - Multi-octave value noise is built on an integer-hash lattice with smoothstep interpolation.
  - Maximum elevation = mountainous/100 × 4,000 m. That is a placeholder anchored on Taiwan's highest peak (about 3,950 m); name it as such.
  - Coastline complexity scales the noise at the shoreline.
  - Outlying islands: exactly the requested number of small offshore islands.
  - Store elevation as integer decimetres (quantised). Sea cells are 0.

A4 Drainage.
  - Fill depressions by priority flood, with ties broken by cell index so the fill is deterministic.
  - Use D8 flow directions and flow accumulation.
  - River cells are those whose accumulation reaches a threshold, and the threshold falls as river density rises.
  - Every river cell must drain to the sea.

A5 Land cover, one class per land cell: urban, forest, wetland, open, barren.
  - Wetland: low, flat ground near rivers and the coast. Its share rises with lowland and wetland.
  - Forest: rises with forested, falls with aridity, and prefers slopes and mid elevations.
  - Barren: high and steep ground, plus dry ground as aridity rises.
  - Urban comes from A6.
  - Everything else is open.

A6 Urban extents.
  - Cities sit on flat lowland near the coast or rivers.
  - The count follows the pattern:
    - one dominant city: one large;
    - several cities: three to five;
    - dispersed towns: many small.
  - The total urban share scales with urban density.
  - Each city has an id, a centre and a cell footprint.
  - Urban extents are used for siting only. They are not a population or demand field (spec §4.1).

A7 Index meanings. Every 0–100 character index means 0 = none and 100 = the most the map type allows (spec §4.1). The numeric mapping from each index to the stage's parameters is yours to set. Put every mapping in one clearly named table of constants, each marked CHOICE with its units, and list them in the report. The design side reviews them against the preview (A10).

A8 Cross-platform arithmetic. World-building arithmetic uses only +, −, ×, ÷ and sqrt:
  - no sin, cos, exp or log;
  - no numpy.random distributions beyond uniform integers and doubles;
  - no dot, matmul or other library reductions whose order can vary.
If something unavoidable needs a transcendental function, quantise its result and say so in the report. CI on both platforms is the proof.

A9 Output: a frozen dataclass holding:
  - the grid (size, cell size in metres, origin);
  - elevation in decimetres;
  - the land mask;
  - flow direction and accumulation;
  - the river mask;
  - land cover;
  - the urban id per cell;
  - the city list;
  - realised statistics:
    - land area in km²;
    - maximum elevation in metres;
    - river length in km;
    - share of each cover class;
    - number of islands.

No file writing inside the stage.

A10 Preview (face validity). `swm preview-terrain RECIPE -o OUT.png` renders a shaded map: sea, elevation, rivers, cover classes, city outlines, a scale bar, and the realised statistics in a caption.
  - Use matplotlib as an optional dependency group ("preview") so the core stays small.
  - The PNG is for the author's eyes and is not part of the identity check.

A11 CLI: `swm terrain RECIPE -o OUT_DIR` writes terrain_stats.yaml (the realised statistics, canonical YAML) and terrain_sha256.txt (the SHA-256 of every array's bytes, in a fixed order). This is written through the recipe io writer, not by the stage.

A12 Tests:
  - Identity (golden): the pilot recipe's terrain array hashes and statistics are checked in, and CI reproduces them on Windows and Linux.
  - Streams: changing terrain_seed changes the terrain; changing root_seed with the same terrain_seed also changes it; no non-terrain stream is drawn.
  - Area: the realised land area is within one cell's area × perimeter tolerance of area_km2 (state the tolerance).
  - Elevation: sea cells are 0; the maximum is at or below the bound; mountainous 0 gives low relief.
  - Drainage: after the fill, every land cell drains to the sea, with no sinks.
  - Monotonic response: at a few settings each, forested raises the forest share, aridity lowers it, lowland and wetland raises the wetland share, urban density raises the urban share, and river density raises river length.
  - The outlying-island count equals the setting.
  - Property: for random valid terrain sections, the stage runs, and the output satisfies the invariants above.

PART B — FOLLOW-UPS FROM WORK ORDER 1 (record as docs/decisions/0004-wo1-review-rulings.md)

B1 Rename every heterogeneity field to heterogeneity_pct. Meaning: the spread of element values around their context-adjusted target, as a percentage of the target (spec §4.4).

B2 Sizes. Any size with node counts up to 20 per layer and land area up to 2,000 km² is Phase 1, whether or not it matches a named preset. Only larger sizes are Phase 5.

B3 Concave transfer form. An exact-tier (or "both") recipe that uses concave is valid, but the buildability check refuses it until Phase 5 with a clear message.

B4 Service weights. Replace "healthcare_first" with "lifeline", and add the end-use class list, both from spec v0.3 §5.
  - End-use classes: tertiary, regional, blood bank, clinic, distribution substation, mast, storage, airport, seaport, depot.
  - Lifeline weights: tertiary 10, regional 7, seaport 7, blood bank 6, airport 6, distribution substation 5, water storage 5, fuel depot 4, clinic 3, mast 1.
  - Equal: all 1.
  - Custom: 0–100 per end-use class.
  - Only end-use classes take weights. Put the tables in the schema with a source note (spec v0.3 §5; the author's judgment on FEMA Community Lifelines categories).
  - The pilot fixture uses lifeline.
  - Record the objective definition in the schema description: weighted service-hours at end-use nodes.

B5 Coverage 0–100% (a validation note at 0). Snapshot age 0–30 years.

B6 CLAUDE.md:
  - Only emit/, manifest/ and recipe/io write files; stages never do.
  - Add swm resolve, swm check-recipe, swm terrain and swm preview-terrain to the §5 CLI line.
  - Add the cross-platform arithmetic rule in A8 to §4.

B7 Schema versioning. Recipe schema version 1 stays open to change until Phase 1 closes (tag v0.1.0), then freezes. Changes before then do not bump the version. Record this. The golden pilot files will change in this work order because of B1 and B4; say so in the pull request.

B8 docs/design/README.md: update the version column (structure v0.3, pilot spec v0.4). Do not edit the design documents themselves.

Acceptance:
- All checks pass locally and in CI on both platforms, with coverage at or above 90%.
- The terrain golden hashes match on both platforms.
- `swm terrain` and `swm preview-terrain` run on the pilot recipe.
- Attach the pilot preview PNG to the pull request, or say where it is, so the author can look at the island.
